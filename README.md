# 归档台 V2

Windows 本地文件整理工具，使用 Python、PySide6 Widgets 与 SQLite。先查看每个文件的目标位置和匹配原因，勾选后执行，再从历史记录按批次撤销。

## 快速试用

本机构建后的入口是 `dist\V2\归档台\归档台.exe`。从 GitHub 获取源码后，可按下方 PowerShell 命令启动或打包。

1. 启动归档台，点击 **创建演示目录**。程序会在系统临时目录生成一组独立的样例，包括同名冲突、一组重复件和一个未匹配文件。每次点击会生成新目录。
2. 在中间清单选中一行，在右侧查看原路径、目标路径、规则和原因。开启 **包含子文件夹**，可看到上海、杭州两个来件目录中的同名交接单。它们字节数相同，内容不同，会产生计划目标冲突。还可以用左侧 **目标根目录 → 更改** 选择另一个已存在的目录或其他盘符。
3. 勾选待移动文件，或使用 **全选可移动项**，点击 **应用选中项** 并阅读确认摘要。
4. 在 **历史** 中查看每项的实际结果。关闭并重新启动后，选择同一批次即可撤销。演示目录会保留，便于稍后验证。

### 重复件与规则方案

- **重复件检查** 使用本次扫描的文件范围。程序先按大小分组，再对候选文件以 1 MiB 为单位读取并计算 SHA-256。报告列出重复组、各文件路径和跳过原因，检查可随时取消。
- 在重复组中勾选一份 **保留**，点击 **加入隔离计划**，工作台会列出其他副本及其在目标根目录下的「隔离区」路径。此时执行项默认未勾选。确认归档时会复核保留项和副本，归档成功的隔离项也可以从历史页撤销。
- **规则中心** 可以新建、复制、启停、调序和试跑规则。扩展名列表中任一项匹配即可。名称通配符（如 `报告-*.pdf`）、来源子目录（含下层）、大小区间（字节）和修改日期区间需要同时满足，区间包含两端。优先级从上到下，首条启用且命中的规则决定目标。工作规则保存在本机，重启可以接着使用。
- 目标子目录示例为 `项目/{year}/{month}/{ext}`。年、月来自文件的**本地修改日期**，扩展名取最后一个后缀并转为不含点的小写，无后缀使用「无扩展名」。规则中心可以选择一个实际文件试跑，查看命中原因和目标。
- 从 **规则方案** 可以导入 V1 或 V2 JSON。遇到同名方案可另存或确认更新。点击 **使用此方案** 才会重新计算工作台预览；文件移动仍需另行勾选和确认。导出使用新的 JSON 文件名。

### 文件夹收件箱

在 **收件箱** 中选择并启用一个目录。应用打开期间约每 3 秒检查该目录顶层，文件至少稳定 5 秒且可安全打开时列入候选。下载临时后缀、重解析点、程序的临时文件以及已记录的输出会被排除。先选候选，再点击载入预览，所有计划仍需手动勾选与确认。

监视目录、稳定观察记录和显式忽略的文件版本都保存在本地数据库。关闭应用会停止监视；重新打开时补扫。只预览过的候选仍可找回。启用收件箱仅授权生成候选。

## 从源码启动

推荐 Windows 10/11 x64 与 Python 3.12 x64。在项目目录打开 PowerShell。以下命令直接使用虚拟环境中的解释器，无须调整脚本执行策略。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe .\main.py
```

依赖文件使用 PySide6-Essentials，其中包含本应用使用的 Qt Core、Gui 和 Widgets。应用运行期间的数据保存在本机。

## 文件操作约定

- 默认扫描选定目录的当前层。开启递归可处理子目录。扫描和移动都会检查重解析点，跳过符号链接及目录联接。
- 目标可以是所选目标根目录内的多级子目录。预览只读取文件信息，目标目录在执行时按需创建。扫描快照优先读取 NTFS 文件变更序号；卷未提供可用序号时，会流式读取内容摘要，以识别恢复原修改时间的等长改写。
- 已有同名文件或目录、同批多项指向相同位置时，清单显示冲突。默认跳过。可以对冲突使用自动编号（如 `交接单 (1).txt`），或输入含扩展名的新文件名。预览会再次计算整个批次的重名情况。已在目标位置的文件跳过。
- 清单可按来源目录、目标目录、命中规则、冲突类型、文件类型或关键字筛选。「批量操作」处理当前筛选范围；底部显示已勾选项数与字节数。执行前会复核文件和规则，发现过期项时会显示待复核；检查明细、重新预览并确认后再执行。
- Windows 执行阶段锁定路径，核对目录身份与源文件快照，使用文件句柄执行禁止覆盖的重命名。源被占用、内容已变化或目标路径被替换等情况按项记入历史。
- 撤销前检查文件身份、大小、修改时间、SHA-256、相关目录身份及原位置占用情况。原位置冲突时保留两边文件，可以在处理冲突后从历史再次手动撤销。整理过程中创建的空目录会保留。
- 跨卷时，在目标卷创建与日志项绑定的独占临时文件，按块复制、校验大小与完整 SHA-256，随后禁止覆盖地提交。确认目标内容和源文件身份后才移除源。当前跨卷处理普通文件，带附加 NTFS 数据流（如部分下载文件的 Internet 区域标记）、特殊属性或多个硬链接的文件会保留并列出原因。目标文件继承目标目录的访问权限。
- **中断恢复** 在启动时后台核对源、目标、绑定临时文件和日志。打开 **历史**，选择标有「可安全继续」的批次并点击 **继续可安全项**。部分复制会验证临时文件身份和已写前缀；目标已提交时会核验两端。点击确认后再次检查并续办。证据不符的项显示「待人工确认」，保留各份文件供核对。
- 取消时保留已完成项及日志。可在历史中撤销成功项；撤销冲突和未完成项各自记录。数据库就地升级，V1 已移动批次可以继续撤销。

历史数据库默认位于 `%LOCALAPPDATA%\ArchiveDesk\history.sqlite3`。同一数据目录只允许一个运行实例。测试可通过环境变量 `ARCHIVE_DESK_DATA_DIR` 指定独立数据目录。

### Windows 验收记录

实测环境为 Windows 11 x64、Python 3.12.14、PySide6 6.12.0，C: 和 D: 是不同的 NTFS 卷。自动化回归 60 项全部通过，七个可见窗口脚本均通过。

| 场景 | 实测结果 |
| --- | --- |
| 实际跨卷归档和恢复 | 3 MiB 以上的样例文件分别在首个 1 MiB 写入后、目标提交且源仍在时强制退出。在新进程的历史页确认继续，再撤销回原卷，两次均通过 SHA-256 核验。 |
| 取消和撤销 | 两次可见窗口验收分别在 4/100、3/100 项完成时取消，其余项保留原位。撤销后 100 项内容均一致。 |
| 规则、隔离与收件箱 | 多条件试跑、改名、编号、待复核、指定保留项、隔离后撤销，以及重启补扫、只预览的候选找回，均通过可见窗口验收。 |
| 历史迁移和异常数据 | 创建 V1 格式数据库后升级并实际撤销旧记录；更换临时副本、改变源内容、原位置占用和附加数据流均有相应回归用例。 |
| 10,000 文件扫描和预览 | 100 个子目录，各 100 份 15 字节合成文件。最后一轮递归扫描 62.417 秒，规划 3.631 秒，8,000 项待移动、2,000 项未匹配，目标目录保持为空。计时不包含生成和清理样例。 |
| 打包验证 | 保留原有 spec，用 PyInstaller 6.22.3 构建 Windows x64 目录版。通过打包程序的可见窗口生成演示、确认移动 5 项、重启、从历史撤销，逐项核对原始 SHA-256 与 SQLite 结果。 |

验证使用进程强制退出模拟指定中断点，未进行物理断电、网络共享盘或非 NTFS 卷验收。若其他进程恰在源移除检查和 Windows 删除标记之间创建附加数据流，程序会在关闭句柄前复查并尝试撤销标记；此时若同时强制终止进程，应用层回撤无法保证执行。

## 构建 Windows 可执行文件

```powershell
.\.venv\Scripts\python.exe -m pip install "PyInstaller>=6.11,<7"
.\.venv\Scripts\python.exe -m PyInstaller --distpath ".\dist\V2" --workpath ".\build\V2" ".\归档台.spec"
& ".\dist\V2\归档台\归档台.exe"
```

分发时复制整个 `dist\V2\归档台` 目录，其中的 `_internal` 包含 Qt 和 Python 运行库。
